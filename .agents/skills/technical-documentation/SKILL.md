# Technical Documentation Skill

- Keep README, architecture, scope, BOM, risk register, API contract and test records aligned with the implementation.
- Mark each item as planned, in progress, tested, hardware-verified or deferred.
- Include units, assumptions, sources, timestamps and version numbers in technical records.
- Draw diagrams with named interfaces and direction arrows; do not hide unknowns.
- Record hardware part numbers and datasheet links before wiring or procurement.
- Keep decision records for architecture changes and dependency additions.
- Never invent performance, accuracy, cost, test outcomes, institutional approval or hardware availability.
- Prefer concise tables, reproducible commands and clear setup instructions.
